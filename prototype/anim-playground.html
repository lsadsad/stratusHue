How it works with your existing SVGs:
Sections 1–5 animate the <img> tag or its wrapper element — your SVG files don't change at all. They're treating the SVG like a bitmap that gets carried along for the ride.

Section 6 (draw-on stroke) is the only one that needs to reach inside the SVG paths. That requires either embedding a <style> block inside the .svg file, or switching from <img> to inline <svg> markup at build time.

How these connect to your real code
Sections 1–5 · CSS only

Your ui.html stays exactly as-is.
Your assets/*.svg files stay exactly as-is.

We add @keyframes to styles.css and wire them to button selectors like:

#nav-up-btn:active .nav-icon {
  animation: nudge-up 0.28s ease-out;
}
#refresh-anchors:active .icon {
  animation: spin-once 0.5s ease-in-out;
}
One npm run build and it's live in the plugin.
Section 6 · Animated SVG (draw-on)

We add a <style> block + @keyframes inside the .svg file. The animation is self-contained and plays when the SVG is displayed — even as a base64 <img>.

<!-- inside ICO-navBack.svg -->
<style>
  .arrow { animation: draw 0.4s ease-out; }
  @keyframes draw {
    from { stroke-dashoffset: 60; }
    to { stroke-dashoffset: 0; }
  }
</style>
Prototype preview: open assets/ICO-navBack.svg directly in a browser tab — the animation runs there first, no build needed.
What Figma exports vs what you need for inline
❌ Figma export (4 problems) 
<svg width="16" height="16" viewBox="0 0 16 16"
     fill="none" xmlns="...">

  <g clip-path="url(#clip0_1848_191524)">

    <path d="M15.5 15.5L11.6..."
      stroke="white"
      stroke-linecap="round"/>

  </g>

  <defs>
    <clipPath id="clip0_1848_191524">
      <rect width="16" height="16" fill="white"/>
    </clipPath>
  </defs>

</svg>
① width/height on root — locks icon size, CSS can't resize it
② clip-path="url(#...)" wrapper — Figma-only ID that conflicts when multiple inline SVGs are on the same page
③ stroke="white" — hardcoded, theme-blind
④ <defs><clipPath> block — redundant (just clips to viewBox), must be removed along with ②
✅ Inline-ready (4 fixes applied) 
<svg viewBox="0 0 16 16"
     fill="none" xmlns="...">

  <path d="M15.5 15.5L11.6..."
    stroke="currentColor"
    stroke-linecap="round"/>

</svg>
① width/height removed — CSS controls size via container
② <g clip-path> wrapper removed — paths promoted to root
③ stroke="currentColor" — inherits from CSS color: property
④ entire <defs> block removed — no orphaned IDs
Lucide is already ✅ on 3 of 4. When you copy from the Lucide website or lucide-static package, icons already use stroke="currentColor", have no clipPath IDs, and no <defs>. The only thing to remove is width="24" height="24" from the root <svg>. That's a one-second edit — no Figma step needed at all.
Live demo — theme-locked vs theme-aware
Switch icon color:
● stroke="white" — locked, ignores color buttons above
Always white — ignores CSS color, ignores theme
● stroke="currentColor" — theme-aware, responds to buttons above
Responds to color: from any parent — CSS variable, theme class, hover state
In practice this means: a disabled button sets opacity: 0.4 and the icon dims automatically. A hover state sets color: var(--theme-accent) and the icon goes blue. A light theme sets color: #1a1a1a and the icon goes dark. Zero extra CSS per icon, zero SVG variants to maintain.
