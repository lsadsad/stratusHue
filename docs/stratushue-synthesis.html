StratusHue — Product Vision

Scaffold → Navigate → Validate across phases and roles

The premise
One recipe, three modes, four roles

A recipe defines what a "complete" file looks like — not just pages, but content, annotations, tokens, and component usage. Scaffold creates the structure. Navigate surfaces progress. Validate audits readiness. The definition of "ready" changes per page and per project phase.

Who works in the file
UX Designer UI Designer Product Content Writer

Deliverables come from three roles: UX (flows, wireframes, interactions), UI (visual design, components, tokens), and Content (strings, microcopy, error states). Product reviews and approves across all three.

The problem: Content writers may not be Figma-native. Their deliverables (strings, copy) need to flow into the design file, but the interface for creating/editing that content should meet them where they are — not force them into Figma's variable panel.

UX signs off UI signs off Content signs off Product approves handoff
What lives where
StratusHue (Figma Plugin)
⬡ Scaffold: Creates pages, content templates, section containers, variable placeholders from recipes. Stamps recipe to file.
⌘ Navigate: Bookmarks, emoji tags, history, sizing. Surfaces pending content variables (🔄 / ✅ status). Lets designers see progress at a glance.
✦ Validate: Design lint (styles). Token audit (variable coverage). Component check (library compliance). Annotation audit (required categories per page). Readiness check (recipe diff). All per-page, phase-aware.
Audience: UX, UI, and Product — people already in Figma. They set up variable structures, apply components, add annotations.

The recipe is the connective tissue

A single recipe JSON defines everything about what "done" looks like for a project type:

① Structure — which pages, what order, emoji prefixes, page dividers
② Content — starter frames, text nodes, section containers, variable placeholders per page
③ Annotations — which annotation categories are required per page (image spec, UX note, asset location, a11y)
④ Tokens — minimum variable coverage thresholds per page (color ≥90%, spacing ≥80%)
⑤ Components — approved libraries, detachment rules, per page (wireframes = relaxed, specs = strict)
↓

Scaffold reads layers ①② to create the file. Validate reads layers ①②③④⑤ to audit it. Same format, different consumers. The recipe grows in depth as the product matures — Phase 3 ships ①②, future phases add ③④⑤.

Open decision — content workflow
Where does content writing happen?

Content writers need to fill in text variables and approve copy. Three approaches, not mutually exclusive:

A. Inside StratusHue
Add a content panel to Navigate mode that lists all text variables on the current page with inline editing. Keeps everything in one plugin, but requires content writers to use Figma.
B. Separate external tool
A web app or Google Sheets add-on that reads/writes Figma variables via REST API. Content writers never open Figma. StratusHue just validates that variables are filled and approved — doesn't own the editing.
C. Hybrid — StratusHue sets up, external fills in
Scaffold creates variable placeholders. Navigate shows status (🔄 / ✅). Validate enforces that all variables are approved before handoff. The actual editing happens wherever the writer is comfortable — Figma, Sheets, or an external tool. StratusHue doesn't care how they got filled, just that they are.

The insight

StratusHue isn't three separate tools bolted together. It's one workflow loop — Scaffold creates what the recipe defines, Navigate tracks progress through it, Validate measures completion against it. The recipe format is the single source of truth that connects all three modes, all four roles, and all project phases. Build the schema right in Phase 3, and everything else layers on top.
